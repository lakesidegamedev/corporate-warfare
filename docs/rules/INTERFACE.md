# Session and phone interaction specification v0.1

## Public Rust session interface

Implement in cw-session, then wrap with UniFFI owned DTOs. The bootstrap engine-info
call stays available for diagnostics. Do not expose World or require Swift to compute
financial identities. No callbacks from Rust into Swift during mutation.

- create_session(ScenarioConfig) -> SessionHandle; configuration contains seed u64,
  scenario enum Founder/Guided, mode Sandbox/FiveYear, dataset hash and Standard difficulty.
- submit(CommandEnvelope) -> CommandReceipt; receipt includes sequence, accepted tick,
  reservation summary, typed rejection and latest revision. Duplicate ID returns original.
- preview(CommandIntent) -> Preview; never reserves/mutates, includes revision and
  assumptions. Submit still validates. Preserve input on stale-preview rejection.
- advance(max_weeks u32) -> AdvanceResult; cap at16, pause after each committed week if
  a mandatory decision appears. Result contains weeks advanced, revision and pause reason.
- overview() -> Overview; investor/group headline amounts, tick, alerts, recent delta.
- query(Query) -> Detail; enum selects typed region/product/firm/facility/ownership/deal/
  debt/insurance/policy/statement/timeline DTO. Paginated lists default50, cap200, cursor
  includes state revision. Stale cursor asks refresh; never silently mixes snapshots.
- export_save() -> bytes; committed tick only, includes envelope metadata.
- import_save(bytes) -> SessionHandle; build new handle first; old handle stays usable
  on validation failure. Size bound initially64MB uncompressed, fail before allocation.

All domain errors are a typed tagged record: InvalidActor, NoAuthority, StaleRevision,
InvalidEntity, InsufficientCash, InsufficientStock, CapacityUnavailable, SolvencyRestriction,
OwnershipCycle, QuoteExpired, LegalReviewRequired, InvalidSave, UnsupportedVersion,
ResourceLimit and InternalFault. Error includes safe message key, affected ID and remedy
route where meaningful. InternalFault retains diagnostic ID, never leaks private paths.

Command envelope: command_id generated by host as high/low u64 fields (128 bits total), actor ID, expected_revision,
submitted_tick and typed intent. Canonical replay assigns monotonic sequence when accepted.
Validate one complete intent before reservation, append accepted command to log and commit
at next boundary. Session owns command ID history for at least current and previous
52 weeks; older ID reuse is rejected by monotonic actor nonce, not reapplied silently.

## Swift ownership and state

One SessionActor owns SessionHandle and a serial executor. View models issue preview,
submit and advance through it. MainActor only handles immutable display data. Advancing
is cancellable between weeks, never inside settlement. Run-speed timer submits at most
one advance request; no accumulated unbounded backlog when a tick is slow. Selecting a
new firm changes view context, not actor authority.

Save manager actor requests committed export from SessionActor, then writes temp+flush+
replace in app Application Support. Last-good and three rolling autosaves plus ten manual
slots. Autosave every four weeks and on stop/background; 13-week milestone backup retains
last four quarters. Export command logs separately when >8MB; keep save under64MB initial
import cap. Memory/time budgets are measured, not silent truncation of future-affecting
state. Revisions advance only on committed transitions; queries/preview never do.

## Exact first phone vertical slice

Screen A Start: Resume (only with valid latest save), New Career, Saves, Settings/About.
New Career chooses Founder/Guided, Sandbox/Five-year, seed optional; Standard default.
No industrial picker requiring advance knowledge in Guided. Founder selects firm name,
region and a facility template with costs. Invalid funding leaves form and shows shortfall.

Screen B Overview: top investor/selected firm context, week/run controls, actual free
cash, four-week cash forecast, last-week EBIT and alerts. Tap Cash opens bridge starting
cash + receipts - operating payments - investment - financing - tax = ending cash.
Group and parent-only amounts are distinct labelled modes. No fake chart data.

Screen C Facility: capacity/output/sold/stock, workers by tier, bottleneck explanation,
price and staffing policy; contract/build actions use previews. After one tick, compare
opening/closing and show actual result against labelled forecast.

Screen D Region comparison: choose up to3, compare labour/cost/demand/freight/quality
flags. Expand action carries selected region/template into the same BuildFacility form.
No different region ID mapping in UI.

Screen E Supply: input stock cover, finite supplier offers, delivered quote and ETA.
Choose volume/term, preview, accept; timeline shows escrow/dispatch/arrival and shortfall.

These five screens use the real session and satisfy the first vertical slice. Corporate
screens follow the screen contracts in EXPERIENCE, using the catalogue above. Every
release command must have a reachable UI path, rejection reason and integration test;
listing commands in this document does not count as implementation.

## Deterministic primitives and save encoding

Choose SplitMix64, pinned algorithm: state +=0x9E3779B97F4A7C15 (wrapping u64);
z=(state xor state>>30)*0xBF58476D1CE4E5B9; z=(z xor z>>27)*0x94D049BB133111EB;
return z xor z>>31. Persist stream state. Subsystem tags are fixed numeric constants:
macro1, events2, AI3, generation4, insurance5, research6. Initialise each from one
SplitMix64 output of master_seed xor tag. Per-entity draws derive their own stream from
subsystem seed xor stable entity handle, so adding an unrelated entity cannot reorder
another's draws. Uniform integer range uses rejection sampling, never modulo bias or
platform float. Decision draws persist once made, not rerolled by opening a screen.

Logical handle is typed u64: low32 slot, high32 generation. Generation increments on
reuse; retired slot at generation overflow is never reused. Slot-to-row mapping separates
logical IDs from dense storage. Save canonical logical slot/generation and stable-sorted
rows. Zero/invalid handle is reserved and rejected.

Canonical hash is BLAKE3 over domain bytes CWSTATE1, schema/rules/data identifiers,
fixed little-endian primitives, length-prefixed UTF8 and stable-ID-sorted entity/queue
records in an explicitly enumerated field list. Include accepted future commands, draw
states, carry remainders and scheduling cursors. Exclude profiling/UI/report caches.
Postcard payload encoding and zstd compression are the save transport; hash authoritative
canonical fields, not compression bytes. Pin introduced dependencies in Cargo.lock.
Envelope checksum also uses BLAKE3 over the encoded payload; validate declared compressed
and decompressed lengths <=64MB, reject decompression beyond that bound. Never allow a
small malicious compressed save to allocate an unbounded world.

Save schema versions the postcard payload layout. Postcard is not self-describing, so adding a
field to any saved struct bumps the schema (`cw_sim::legacy::LAYOUT`) and keeps a frozen copy of
each changed struct as it was, converted on load with neutral defaults for the new fields
(empty, zero or false, never invented history). The engine reads every released schema from
`MIN_SCHEMA_VERSION` up and refuses newer ones with a version error. Schema 1 covers releases
through 1.8 preview 2; schema 2 adds plant cut yields, the production lock and household
wanted/unmet demand; schema 3 (1.9) adds the scenario timeline cursor (`SystemicState.timeline`:
mode, the events with their play dates and which have been announced and fired, and the price
shocks and credit squeezes in force). A schema 2 save loads with the timeline off and empty: dates
are never invented for weeks already played. A save written by 3 is refused by a build that reads
only up to 2 with the usual unsupported version message. Data kept outside the payload (custom scenario, currencies, freight read-out,
history archives, and in 1.9 the chapter state) travels in tagged trailers that older readers skip, independent of the schema. The `CHAP` trailer (last, after `SYST`) holds the chapters and board mandates on offer and in force, the player's chapter log and the achievements earned (`World.chapters`, see CORPORATE.md, Chapters and mandates). Unlike `HIST` and `SYST` it affects play, so `canonical_hash` folds its bytes in whenever it is not empty; being outside the payload it needs no schema bump or frozen layout. A save without it (every earlier save) loads with it empty. The command `ChooseMandate` is a new last variant of the command enum, so older logs keep their variant numbers. The `EXEC` trailer (after `CHAP`, any order with `MAIL`) holds the executives, the pool of people who can be hired, the event log and the board's record (`World.executives`, see CORPORATE.md, Executives). It affects play, so `canonical_hash` folds its bytes in whenever it is not empty; it needs no schema bump because it is outside the payload, like `CHAP`: a save without it (every earlier save) loads with it empty and the pool is drawn in the next week, which is not invented history. The reason for a trailer rather than a schema bump is that the state is a new, self-contained list that no existing struct reads. `HireExecutive`, `DismissExecutive` and `PoachExecutive` are the last three variants of the command enum. The `EARN` trailer (any order with `CHAP` and `MAIL`) holds the analyst estimates, guidance, credibility and the results log (`World.earnings`, see CORPORATE.md, Earnings season). It affects play, so `canonical_hash` folds its bytes in whenever it is not empty; being outside the payload it needs no schema bump or frozen layout, for the same reason as `CHAP`. A save without it loads with it empty and the first estimates are written at the next quarter's close, never invented for weeks already played. The command `GiveGuidance` is a new last variant of the command enum after `ChooseMandate`. The campaign reasons `MissedGuidance` and `Overvalued` are appended to the saved `Reason` enum, so every earlier save decodes unchanged.
Each schema change adds a save written by the last released build as a test fixture.

## Bounded financial history

Keep authoritative current account balances, construction/cost bases, receivables/payables,
loan/policy schedules, tax loss buckets and all other future-affecting state permanently.
Detailed posting journal retains13 weeks; weekly account summaries104 weeks; quarterly
financial statements52 quarters. Older closed history compacts into opening balances,
aggregate lifetime/career statistics and a chained journal hash. Compaction never changes
cash, retained earnings, inventory cost, claims, future obligations or canonical future
outcomes. Retain enough tax buckets for the prescribed four-year loss carry. Optional
full audit/command history exports separately and cannot make saves grow without bound.
Test compaction against an unpruned reference at week104,260,1560. A visible historic
chart labels its retained interval; it never invents missing old transaction detail.
